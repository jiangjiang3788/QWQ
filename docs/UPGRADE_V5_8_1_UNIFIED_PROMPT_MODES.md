# QWQ V5.8.1：统一私聊模式与旁支模型任务项目化

## 本版定位

V5.8.0 先完成默认私聊的角色扮演提示词分层。V5.8.1 完成第二步：默认私聊、自定义 Prompt、剧情节点不再各自维护一套完整提示词，而是共用同一套实际发送项目；通话、日记和小剧场则复用相同的核心档案与来源登记，但保持各自简短的任务结构。

这次没有增加拖拽排序、每段独立预算、权限系统或复杂工作流。单人使用仍然只需要维护核心档案、世界书、记忆和少量现有设置。

## 一、默认私聊、自定义规则、剧情节点统一顺序

三种私聊模式现在都由同一个项目构建器生成：

1. 00 会话总规则
2. 01 世界书·身份前
3. 02 核心档案
4. 03 世界书·身份后
5. 04 长期关系记忆
6. 05 世界书·场景后置
7. 06 当前与相关记忆
8. 07 当前环境
9. 08 自定义规则
10. 09 互动规则
11. 10 输出规则
12. 11 后台写入
13. 12 消息说明（在消息元数据协议追加后出现）

空项目不会发送，也不会在悬浮球中占位。悬浮球顺序直接来自最终请求中的项目标签。

## 二、自定义 Prompt 改成固定“自定义规则”插槽

自定义 Prompt 不再接管整份系统提示词，只提供额外规则。

固定由系统负责发送的内容包括：

- 核心档案；
- 三个世界书位置；
- 长期记忆和当前相关记忆；
- 当前环境；
- 互动规则；
- 输出格式；
- 后台写入协议。

旧模板中的以下结构会自动剥离，防止重复注入：

- `{{世界书_前}}`、`{{世界书_中}}`、`{{世界书_后}}`；
- `{{角色人设}}`、`{{用户人设}}`、`{{共同回忆}}`；
- `<char_settings>`、`<user_settings>`、`<memoir>`；
- 默认会话说明、旧时间占位、旧线上模式说明；
- `{{在线逻辑规则}}`、`{{输出格式}}` 等结构占位。

用户自己额外写入的规则会保留在 `08 自定义规则` 中。`{{user}}`、`{{char}}`、当前时间、角色名、用户称呼和角色状态仍会在最终发送时替换，不修改原始模板。

自定义 Prompt 设置页的默认模板现为空白，界面说明也改成“只填写额外规则”。

## 三、剧情节点接入同一项目骨架

节点不再生成一份与普通私聊完全不同的 system prompt。

节点信息放入：

- `00 会话总规则`：说明正在进行哪个节点以及线上/线下模式；
- `05 世界书·场景后置`：节点绑定的线下文风世界书；
- `07 当前环境`：节点指令、扩展规则、节点前的线上背景和本轮环境；
- `10 输出规则`：线上或线下基础格式、节点注入格式和节点自定义格式。

### 节点记忆隔离

当节点的“读取记忆”关闭时：

- 核心档案仍然发送，角色身份和双方关系不会丢失；
- 长期关系记忆不发送；
- 当前与相关记忆不发送；
- 节点内聊天历史仍按原规则截断。

这使“记忆隔离”只隔离动态经历，不会把角色变成没有身份的空白模型。

### 线下节点

线下节点：

- 使用线下互动规则和线下输出格式；
- 不发送角色自主收藏写入协议；
- 节点自定义格式中的 `{{char}}` / `{{user}}` 会正常替换。

## 四、通话请求项目化

实时通话继续保持通话专用输出格式，但资料顺序统一为：

- 会话规则；
- 世界书·身份前；
- 核心档案；
- 世界书·身份后；
- 长期关系记忆；
- 世界书·场景后置；
- 当前与相关记忆；
- 通话环境；
- 通话互动规则；
- 通话输出规则；
- 实际通话消息。

通话不再单独读取旧 `persona` / `myPersona` 作为主要身份，而是复用核心档案；核心档案为空时才回退旧字段。通话前文字记录也改为遵守 Proment 的历史策略，不再受角色旧 `maxMemory` 二次截断。

## 五、日记与小剧场复用核心档案

### 日记

私聊日记的默认第一人称模式会使用与主聊天相同的核心档案字段分组。请求来源拆为：

- 核心档案；
- 日记背景世界书；
- 过往日记参考；
- 日记风格要求；
- 本次实际选择的聊天范围；
- 剩余任务规则和 XML 输出要求。

聊天来源正文只生成一次，避免同一范围在操作记录中重复登记。

### 小剧场

手动小剧场和角色主动小剧场都优先读取核心档案：

- 角色、用户、双方关系由同一份核心档案提供；
- 核心档案为空时才回退旧角色人设；
- 世界书、日记参考、最近聊天和额外创作要求继续作为独立任务来源；
- 用户在手动小剧场中主动选择的人设预设仍可作为本次任务的明确覆盖信息。

小剧场仍然是独立创作任务，不强制套用主聊天的十三段完整结构。

## 六、旁支任务来源不再重复整份请求

以前日记、小剧场等任务即使已经登记了身份、世界书和输入，操作记录仍会把完整 Prompt 再显示为“任务指令”，造成内容重复。

V5.8.1 会先在最终请求中定位已登记来源的精确文本，只把未覆盖的部分保留为“任务指令”，通常包括：

- 任务目标；
- 风格要求；
- 输出格式；
- 必要包装文字。

身份、世界书、聊天来源不会再在“任务指令”中重复一遍。

## 七、核心档案和占位符原则不变

- 核心档案仍是角色、用户和双方关系的身份主数据；
- 按字段分类渲染；
- 存储在记忆表，发送时前置到身份层；
- `{{char}}` / `{{user}}` 只在最终请求中替换；
- 原始记忆表、世界书和备份数据不会被改写；
- 核心档案有内容时不再重复发送旧角色人设和旧用户人设。

## 八、实际备份验证

使用用户提供的精简备份进行了只读验证：

- 成功读取实际角色和世界书；
- 能生成统一项目 Prompt；
- 核心档案存在并位于身份前置层；
- `{{char}}` / `{{user}}` 在最终请求中已正确替换；
- 悬浮球来源从 `00 会话总规则` 开始，并包含 `02 核心档案`；
- 验证过程不修改原备份；
- 私人正文、接口密钥和备份文件未打入代码压缩包。

## 九、当前边界

- 群聊仍使用群聊自己的提示词逻辑；
- 图片识别、生图、关系判断等工具型任务继续使用简短任务模板；
- 日记摘要模式以客观总结为目标，不强制注入核心档案；
- 手动小剧场明确选择的用户人设预设可覆盖本次创作身份，这是用户主动行为，不视为重复来源。

至此，原计划中的两步已经完成：主私聊的所有模式统一，通话、日记和小剧场也已经完成资料复用和来源去重。
