# 动态记忆系统 V3 第一版（修订 1.1）

## 核心原则

- `character.memoryStore` 是每个角色记忆的唯一真源。
- 表名、字段、短期/中期/长期层级全部由用户配置，不在业务代码中写死表格。
- 所有写入都直接进入正式表，不再有候选、审核、运行态、置信度、版本回退或向量记忆。
- 每条记录固定带有：分类、标签、信息来源、创建时间、更新时间。
- 信息来源只有：`用户明确`、`AI判断`。

## 三种层级

- 短期：正常聊天回复末尾携带 `<memory_ops>`，直接写入启用的短期表。
- 中期：从用户选定的短期表积累正式记录，按自定义条数、分类和标签过滤，经总结 API 整理后直接写入中期表。
- 长期：只允许在界面中手动新增、编辑和删除；AI聊天不能自动写入。

## 上下文注入

记录只有在以下条件之一成立时进入聊天上下文：

1. 记录分类出现在近期对话中；
2. 至少一个记录标签出现在近期对话中；
3. 记录带有用户设置的“始终注入”标签。

带有“禁止注入”标签的记录不会进入上下文。每张表只保留分类过滤、必须包含标签和排除标签三类注入规则；最终注入条数由全局设置控制。

## 唯一数据结构

```json
{
  "version": 1,
  "settings": {
    "enabled": true,
    "allowAiJudgment": true,
    "roundNoticeEnabled": true,
    "injectionMaxRecords": 24,
    "tagBehaviors": {
      "alwaysInject": ["始终注入"],
      "neverInject": ["不进入上下文"]
    }
  },
  "tables": [],
  "records": {
    "table_id": []
  }
}
```

表定义中包含动态字段、KV/Rows类型、记忆层级、短期写入规则、分类/标签自动归档路由、中期积累规则、聊天USER状态栏来源和分类/标签注入规则。正式记录只保存在 `records`。

## 旧数据处理

首次打开时：

- 将旧正式表转换为 `memoryStore`；
- 丢弃旧候选审核表、运行态、审核批次和其他派生数据；
- 删除角色上的旧 `memoryTables` 与 `vectorMemory`；
- 清空全局旧模板库；
- 固定聊天只从动态记忆表读取记忆。

原备份文件不会被修改。

## 主要文件

- `js/features/memory/simple_memory_v1.js`：唯一记忆内核、动态表、直写、中期积累、分类标签注入和界面。
- `css/modules/memory_simple_v1.css`：动态记忆界面。
- `js/modules/chat_ai.js`：聊天只注入动态记忆表。
- `js/db.js`：初始化 `memoryStore` 并删除旧并行记忆数据。


## 修订 1.1 界面和回执

- 每轮聊天均提示记忆处理结果；无更新也会提示，可在记忆设置关闭。
- KV表纵向显示左字段/右值；Rows表长内容截断，编辑器始终保留全文。
- 事件ID字段默认隐藏，值不会被删除。
- 聊天顶部状态栏由用户指定的一张短期KV表提供，只显示USER状态。
- 短期自动写入增加分类/标签路由校验，至少匹配一个配置项才进入目标表。

最新行为说明见 `docs/V1_2_BEHAVIOR.md`。
