# V1.5.2 状态时间与多表写入修复

## 当前状态记录时间

USER状态来源表为短期KV表且开启“USER状态栏来源”时，以下字段名会被识别为系统时间字段：

- 状态记录时间
- 当前记录时间
- 记录时间
- 状态更新时间

每次该状态表被新增或更新，程序会覆盖该字段为浏览器本地时间：

`YYYY-MM-DD HH:mm:ss`

示例：`2026-07-25 13:45:08`

该值不再由AI决定，因此不会只写到日期，也不会出现模型格式漂移。

## 为什么之前主要只有当前状态更新

1. USER状态表设置了 `mustUpdateEveryRound=true`，提示要求每轮必须写。
2. 其他短期Rows表只是“有合适内容时可写”，没有逐表完成检查的强制步骤。
3. 状态表包含大量当前值，占用的提示篇幅远大于其他表，模型容易完成强制状态操作后停止。
4. Rows表的写入定义没有提供现有记录摘要与 `recordId`。当用户说“之前那个事项完成了”时，模型不知道应该更新哪一行，往往选择不写以避免重复。
5. 导入的旧状态提取规则仍含有“运行态”等旧架构描述，与当前直接写正式表的规则冲突。

## 本版处理

- 每轮必须逐张检查所有启用的短期表。
- 当前状态写入不能替代其他表写入。
- 同一轮信息符合多个表时，允许同时生成多个operation。
- Rows表提供最多6条相关或最近记录，包括 `recordId`、分类、标签、更新时间与精简字段值。
- 命中旧记录时使用 `recordId` 执行upsert；确实是新事项时才add。
- 普通短期表排在状态表之前，状态表仍保持每轮必检。
- 旧提示中的运行态、候选、审核等词不再改变直接正式写入规则。

## 不变的部分

- 分类和标签不阻止写入。
- 不恢复候选池、审核、运行态或回退历史。
- 上下文引用仍只读取最近1条聊天消息。
- 长期表仍只允许手动写入。
- 中期表仍通过积累规则写入。
