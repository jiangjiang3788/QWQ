# QWQ V5.7.0：消息收藏并入角色记忆表

## 最终行为

消息收藏不再拥有独立 App、列表页、详情页或独立 Prompt 来源。

收藏发生在哪个角色的私聊中，就写入该角色自己的 `memoryStore`，固定表 ID 为：

```text
v5_message_favorites
```

表名为“收藏记忆”。用户点击收藏和角色自主收藏使用同一张表，不再按“我的收藏／角色收藏”拆成两套列表，也没有跨角色权限和共享范围。

## 表格字段

界面中显示：

- 标签
- 收藏方：用户、角色，或双方
- 发送方
- 内容
- 收藏寄语
- 消息时间

标题被彻底隐藏，保存收藏不要求标题。底层仍保存原消息 ID、旧收藏 ID、原始内容和内容类型，用于去重、转换和维护，但这些技术字段不会展示给模型或作为主要界面信息。

## 收藏操作

### 用户收藏

聊天中的单条收藏、多选收藏和合并收藏仍保留。点击后直接写入当前角色的“收藏记忆”表，不再打开收藏页面，也不弹出标题或标签表单。

程序会根据正文自动生成初始标签；标签可随后在记忆表内直接修改。

### 角色自主收藏

角色开启“角色自主收藏”后，模型使用隐藏协议：

```xml
<favorite_ops>
{"items":[{"messageId":"msg_123","tags":["家庭","健康"],"note":"记得关心复查"}]}
</favorite_ops>
```

程序只接受消息 ID、标签和寄语。收藏正文、发送方和消息时间必须从当前聊天历史读取，模型不能重写正文或生成标题。每轮最多处理三条。

## 标签召回

收藏不再全量发送，也不再生成 `<favorite_inventory>`。

“收藏记忆”作为结构化记忆的一张相关召回表参与请求：

- 只使用本轮尚未回复的用户消息匹配标签；
- 不使用角色上一轮回复触发收藏；
- 明确的 `#标签` 具有最高优先级；
- 普通完整标签命中其次；
- 默认每轮最多发送 5 条，可在记忆设置中调整为 1—20 条；
- 没有标签命中时发送 0 条；
- Proment 预算不足时整条排除，不从收藏正文中间截断。

悬浮球只在“结构化记忆 → 收藏记忆”中展示本轮实际发送的记录，不再出现独立“收藏盘点”。

## 旧数据自动转换

应用启动后会执行一次旧收藏转换：

1. 读取旧 `db.favorites`；
2. 根据 `characterId` 或私聊 `chatId` 找到所属角色；
3. 写入该角色的“收藏记忆”表；
4. 同一角色、同一原消息的用户收藏和角色收藏合并为一行；
5. “收藏方”合并为“用户、角色”；
6. 寄语合并并去重；
7. 为没有标签的旧收藏自动生成初始标签；
8. 成功转换后清空旧 `db.favorites`；
9. 无法关联角色或正文为空的记录保存到 `db.favoriteMigrationArchive.unmatched`，不会静默丢弃。

转换完成会显示新增、合并和未关联数量。隐藏字段保留旧收藏 ID，重复运行不会制造同一消息的重复记录。

本代码包不包含浏览器 IndexedDB 中的私人收藏正文。覆盖程序并首次启动后，转换逻辑会直接处理该浏览器现有的数据。

## 已删除内容

- 首页／Apps 中的收藏入口；
- 收藏列表页和收藏详情页；
- 收藏页面专用 CSS；
- “角色知晓我的收藏”开关；
- “仅当前角色／所有角色收藏”范围设置；
- 收藏独立来源 `collection.relevant`；
- `<favorite_inventory>` 全量注入；
- 用户收藏和角色收藏的二级盘点 UI；
- 收藏标题；
- 命中次数及“何时命中过”的追踪。

## 数据版本

- QWQ 包版本：5.7.0
- MemoryV5 版本：5.7.0
- `STORE_VERSION`：仍为 3

保持 `STORE_VERSION=3`，现有角色记忆不会因为升级被重建为空表。
