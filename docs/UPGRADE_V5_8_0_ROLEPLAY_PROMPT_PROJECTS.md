# QWQ V5.8.0 第一版：角色扮演提示词分层与核心档案字段分组

## 版本定位

V5.8.0 是提示词发送顺序重构的第一版，优先完整覆盖当前实际备份所使用的“默认私聊”路径。

这一版不把世界书、记忆、角色资料按代码功能集中到一个大分类，而是按模型实际阅读顺序组装成连续项目。悬浮球直接读取这些项目，不再用“最终系统提示词减去已知来源”的方式制造巨大的“核心系统规则”。

## 默认私聊的实际发送顺序

仅在对应内容非空时生成项目标签：

1. `session_rules`：会话总规则、当前时间、模式、动态年龄与时区。
2. `worldbook_identity_before`：世界书·身份前，位于核心档案之前。
3. `identity_core`：核心档案，作为角色、用户与关系的身份锚点。
4. `worldbook_identity_after`：世界书·身份后，位于核心档案之后、长期记忆之前。
5. `long_term_memory`：长期关系记忆与群聊长期补充。
6. `worldbook_scene_after`：世界书·场景后置，位于长期记忆之后、当前相关记忆之前。
7. `current_related_memory`：当前状态、收藏、待办与其他本轮相关记忆。
8. `current_environment`：天气、拉黑历史、主题变化等临时环境。
9. `interaction_rules`：消息理解、角色行为和可选能力。
10. `output_formats`：输出格式、回复节奏与防复读要求。
11. `background_write`：收藏写入与记忆表写入协议。
12. `message_metadata_protocol`：历史消息时间元数据说明。

系统提示词之后仍依次发送聊天历史、本轮用户输入、控制尾部、工具和请求参数。

## 核心档案

核心档案仍然保存在角色的 `v5_core_profile` KV 表中，不拆数据库、不迁移现有字段。

发送时读取每个可见字段的 `category`，按照以下优先顺序分组：

- 角色档案
- 用户档案
- 双方关系
- 其他自定义分类

输出形式：

```text
【角色档案】
字段名: 字段值

【用户档案】
字段名: 字段值

【双方关系】
字段名: 字段值
```

只要核心档案存在实际内容，它就是身份资料的主要发送来源。旧 `persona` 和 `myPersona` 只在核心档案为空时回退，避免同一人设重复发送或发生冲突。

## `{{user}}` 与 `{{char}}`

这两个占位符与 SillyTavern 的使用习惯一致：

- `{{user}}`：当前角色绑定的用户称呼。
- `{{char}}`：当前角色名；论坛马甲绑定真实角色时使用真实角色名。

占位符只在最终提示词序列化时替换。记忆表、世界书和备份中的原始内容不会被改写，因此更换称呼或角色名后仍可重新正确渲染。

第一版同时为自定义 Prompt 和剧情节点补上了 `{{user}}` / `{{char}}` 双占位符替换，但这两条路径仍保留原有整体组装结构。

## 世界书

原值不转换，只修改显示名称与真实语义：

- `before` → 身份前
- `middle` → 身份后
- `after` → 场景后置

继续只保留一个世界书总预算。处理方式改为：

1. 汇总三个位置的全部候选条目。
2. 按常驻、本轮用户消息命中、最近对话命中、权重和原顺序选择。
3. 选择阶段不因 before/middle/after 位置提前消耗预算。
4. 选中后再放回三个真实插入位置。
5. 条目只能整条发送；预算不足时整条排除，不再截断半条正文。

## 记忆层级

- 核心档案：身份定义层，不与普通动态记忆混合展示。
- 中期总结、稳定长期记忆及其他长期表：进入“长期关系记忆”。
- 当前状态、收藏记忆、待办与近期事项、想法、物品、日常观察等：进入“当前与相关记忆”。
- 收藏记忆虽然长期保存，但只在标签与本轮用户消息相关时召回，并靠近聊天历史发送，不会混进长期关系层。

动态记忆仍按完整记录选择，不从记录中间截断。

## 悬浮球

默认私聊请求按照最终项目顺序展示：

- 00 会话总规则
- 01 世界书·身份前
- 02 核心档案
- 03 世界书·身份后
- 04 长期关系记忆
- 05 世界书·场景后置
- 06 当前与相关记忆
- 07 当前环境
- 08 互动规则
- 09 输出规则
- 10 后台写入
- 11 消息说明
- 聊天历史
- 本轮用户输入
- 请求控制尾部
- 工具与请求参数

空项目不显示。核心档案和记忆项目按字段分类或记忆表进行二级分组。

正常项目全部精确覆盖时，不再出现“核心系统规则”。只有最终请求里确实存在未被任何项目标签覆盖的非空文字时，才显示“未归类内容（需要检查）”。

聊天 Token 分布也改为直接按同一组项目标签计算，不再显示与真实请求不一致的旧“角色人设 / 用户人设 / 系统规则”估算。

## 使用实际备份进行的只读验证

实际备份只用于本地读取和验证，没有写入本代码包。

验证结果：

- 识别到核心档案的“角色档案、用户档案、双方关系”三个字段分类，并按该顺序发送。
- `{{user}}` 和 `{{char}}` 在最终请求中均已替换，原始表格内容未修改。
- 核心档案存在时，旧角色人设和旧用户人设没有重复进入默认请求。
- 当前实际世界书进入“身份前”位置；未启用或未命中的位置不生成空段落。
- 收藏和其他本轮相关记录进入“当前与相关记忆”。
- 最终请求来源全部对账，未出现“未归类内容”。

备份中的接口配置、私人正文和聊天内容没有进入测试文件、说明文档或压缩包。

## 为什么分为两步

一个版本可以完成当前实际使用路径，V5.8.0 已经完成这一部分。继续把所有分支一次性同时重写，会增加自定义 Prompt、剧情节点、通话、日记和小剧场等非主路径的回归风险。

第二步计划：

- 让自定义 Prompt 与剧情节点也完全使用同一项目骨架，而不只是支持双占位符。
- 对通话、日记、小剧场等独立模型任务分别建立精简的任务项目，不强行套用主聊天结构。
- 根据第一版实际悬浮球记录再处理重复规则和段落长度，不预先增加复杂配置。
