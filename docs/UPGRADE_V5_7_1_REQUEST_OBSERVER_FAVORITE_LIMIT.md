# QWQ 5.7.1 修改说明

## 1. 悬浮球与模型请求

代码核查结论：旧版点击悬浮球本身只切换操作中心的显示状态，不会主动暂停请求；但项目中存在两个容易造成误解或误触中止的用户入口：

- 聊天扩展面板中的“暂停调用”；
- 悬浮球操作中心运行中任务旁的“取消／取消本次操作”。

V5.7.1 已删除这三个可见控制。悬浮球现在是只读观察面板：打开、关闭、查看详情和展开来源均不调用 `AbortController.abort()`，也不调用操作运行时的取消接口。

内部 `AbortController` 仍保留，用于请求超时、网络异常和任务清理。这不是悬浮球交互功能，不能从悬浮球触发。

PROMENT 设置页原有的“取消全部 AI 请求”属于独立的显式应急控制，本次未删除；它与点击悬浮球无关。

## 2. 收藏每轮发送上限

V5.7.0 已经可以在“记忆设置”中把默认 5 条改为 1—20 条，但存在 20 条硬上限，并且不能输入 0。

V5.7.1 调整为：

- 默认仍为 5；
- 可以输入任意非负整数；
- 取消 20 条硬上限；
- 输入 0 表示不设置收藏独立条数上限；
- 现有角色已经保存的数值继续保留。

即使输入 0，收藏仍然受到两个总量保护：

1. “上下文最多记录数”；
2. PROMENT 的结构化记忆字符预算。

因此 0 的含义是“不再额外按收藏条数截断”，并不是绕过整个模型上下文容量。

## 4. 验收结果

- 点击悬浮球不会暂停、取消或重发请求；
- 悬浮球内没有运行中任务取消按钮；
- 聊天扩展面板没有“暂停调用”；
- 收藏上限 5、7 等正整数均按设置生效；

- 仍会由全局记录数和字符预算进行最终治理。
