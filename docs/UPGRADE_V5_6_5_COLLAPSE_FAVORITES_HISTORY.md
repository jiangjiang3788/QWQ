# QWQ V5.6.5：来源折叠、收藏盘点与聊天历史精简

## 目标

本次只收敛模型请求详情的展示与收藏来源逻辑，不改变聊天历史数量策略、结构化记忆写入机制或模型接口格式。

## 1. 折叠层级重新统一

模型请求中的每个一级来源均使用可折叠标题，默认收起正文，包括“核心系统规则”“角色档案”“世界书”“结构化记忆”“收藏盘点”“聊天历史”等。

含有多条数据的来源使用二级折叠列表：

- 世界书：每个条目单独折叠；
- 结构化记忆：每张表中的每条实际记录单独折叠；
- 收藏盘点：每条用户收藏或角色收藏单独折叠；
- 其他有明细的来源：统一采用相同结构。

聊天历史是唯一的效率例外：一级“聊天历史”仍可折叠，但展开后不再为每条消息增加一层点击，只显示紧凑消息行。

## 2. 收藏从单类展示改为完整盘点

旧逻辑只把“用户收藏”写入角色感知 Prompt，因此模型请求详情里只能看到用户收藏。

新逻辑在角色开启收藏感知时，同时整理：

- 用户收藏：继续遵循角色设置中的“当前对话 / 所有对话”范围；
- 角色收藏：只读取当前角色自己收藏的用户消息，绝不混入其他角色的收藏。

最终 Prompt 使用一个连续的 `<favorite_inventory>` 区块，内部区分：

- `<user_favorites>`；
- `<character_favorites>`。

请求详情标题直接显示数量，例如：

`收藏盘点（用户 6 · 角色 3）`

每条内容展示会话、发送方、实际消息正文及存在的寄语，不以收藏 ID 作为主要信息。旧请求中的“【用户收藏的内容】”仍可兼容读取，但只能还原当时实际发送的用户收藏。

## 3. 聊天历史改为三项信息

聊天历史消息行仅保留：

- 发送方；
- 发送时间；
- 实际内容。

界面会隐藏仅供模型使用的：

- `[id:...]`；
- `<message_meta ... />`；
- 独立 UTC 时区行；
- `#1 / #2` 等展示序号；
- “已发送 · 字符数”等逐条重复状态。

底层最终请求仍保留原始 ID 与时间元数据，方便模型理解时序和执行角色收藏；这里只是把显示层整理为可读信息，不篡改网络请求。

## 4. 数据真实性

收藏数量、聊天历史数量和来源正文均来自最终请求的 `contextManifest`。V5.6.5 补齐了悬浮球读取 manifest 来源列表的统一函数，并在消息明细中记录角色类型和发送时间元数据。

最新一次操作保留完整正文；更旧操作仍按原有会话存储预算逐步压缩。旧记录没有保存的正文无法追溯补齐。
