# QWQ V5.8.2：角色自主收藏改为稀有动作

## 问题根因

V5.8.1 的收藏协议虽然写了“重要消息”和“没有时不输出”，但紧接着使用了“在正常回复末尾追加一次”的命令式表述，并提供了完整 JSON 示例。对部分模型来说，这会把收藏理解成每轮必须完成的后台任务。

旧版代码反而包含更明确的收藏标准：梦想、价值观、重要经历、关系转折、明确偏好，并强调“不要过度收藏”。V5.8.2 保留新记忆表结构，同时恢复并加强这类判断标准。

## 新收藏原则

角色自主收藏现在被定义为“稀有动作”：

- 默认不收藏；
- 绝大多数普通对话不应产生收藏；
- 只保留角色真正想长期珍藏的用户原话；
- 普通事实和状态优先交给结构化记忆，不应同时写入收藏；
- 每轮最多接受一条角色收藏。

允许收藏的典型情况：

- 用户首次透露未来多轮仍有价值的稳定事实、重要偏好、边界、梦想或关键经历；
- 双方关系出现明确转折，形成重要约定、承诺或共同决定；
- 某句话对角色本人具有强烈、独特的情感意义，值得长期保存原话。

明确排除：

- 寒暄、问候、表情、普通问答、临时安排、日常状态和随口一句；
- 已知、已收藏或只是换种说法重复的信息；
- 仅仅“可能有点用”、更适合普通结构化记忆的内容。

## 请求侧约束

以前只要开启角色自主收藏，聊天历史中所有用户消息都会添加 `[id:消息ID]`。模型每轮都能从整个历史中重新挑选消息，容易不断产生收藏。

现在只给“本轮尚未回复的真实用户消息”添加 ID：

- 上一条角色回复之前的历史消息不再提供收藏 ID；
- 手机控制代发、系统消息、后台消息不作为候选；
- 后台回复、对话总结、角色独白和线下节点不发送自主收藏协议；
- 连续发送的多条本轮用户消息可以作为候选，但最终最多收藏一条。

## 程序侧防线

即使模型仍然错误输出收藏指令，程序还会执行第二次校验：

1. 消息必须属于本轮候选范围；
2. 收藏寄语必须说明为什么值得长期珍藏；
3. “好的”“收到”“哈哈”“晚安”等低信息量内容会被拒绝；
4. 表情包、无正文图片等占位内容会被拒绝；
5. 同一消息已经由角色收藏时不再重复更新；
6. 收藏表中已有相同或近似相同原话时不再新增；
7. 每轮只解析并接受一条收藏指令。

用户手动收藏不经过这些限制。手动收藏仍然表示用户明确决定保存，任何一句话都可以收藏。

## 收藏与普通记忆的分工

- `favorite_ops`：保留极少数有情感价值、值得珍藏的用户原话；
- `memory_ops`：更新事实、状态、事件、待办、关系认知等结构化信息。

提示词会明确要求模型不要在同一轮把同一信息同时写入两处。

## 数据影响

- 不修改已有收藏记录；
- 不删除用户历史数据；
- 不改变收藏表字段和标签召回；
- 只影响安装后新产生的角色自主收藏；
- 用户提供的实际备份仅用于只读结构兼容验证，未复制进代码包、测试或文档。

## 后续可选优化

当前最值得继续做的不是增加更多设置，而是对历史角色收藏做一次可预览的精简整理：识别重复原话、日常寒暄和低价值记录，再由用户确认删除。该步骤不应自动执行，以免误删具有私人意义的一句话。
