# V5.4.0 原地升级与范围说明

## 一、升级不会重置记忆
本版沿用 V5.3 的数据结构和 `STORE_VERSION=3`。覆盖代码后，程序继续从原域名、端口或应用环境的本地存储读取现有9张表和记录。

升级前仍建议执行一次“导出全部”。不要更换域名、端口或应用包名，也不要清除站点数据。

## 二、明确停用的业务
以下能力不再进入主聊天 Prompt，不再解析模型对应指令，也不再提供设置入口：

1. 节点摘要与 `<summary>` 输出协议；
2. 亲属卡和消费记录的角色感知；
3. 偷看手机记录；
4. 冒充角色发送消息记录；
5. 角色手机控制权限和控制指令；
6. 权限撤回事件；
7. 角色控制其他聊天的历史；
8. 大号/小号聊天记忆互通；
9. 双语输出格式和双语规则。

旧数据采取“保留但冻结”策略：不会主动删除，正常业务不再读取、写入或发送。历史双语气泡、亲属卡消息等兼容渲染代码暂时保留，以免旧聊天记录显示异常；不可达的旧辅助函数将在 V5.4.4 统一物理清理。

## 三、防泄漏边界
新增 `deprecated_feature_policy.js`，在以下阶段统一保护：

- 角色和数据库运行设置归零；
- AI 历史过滤；
- 私聊 system Prompt 生成后清理；
- 最终 Provider 请求体形成后再次清理；
- 模型返回进入消息拆分前清理；
- 请求 Manifest 检查停用来源标签。

该策略只检查系统侧注入内容，不会因为用户在普通消息中提到“亲属卡”“双语”等词而拦截聊天。

## 四、统一注册中心第一阶段
新增：

- `js/core/context_source_registry.js`
- `js/core/deprecated_feature_policy.js`

当前注册表覆盖以下领域：

- Prompt核心规则；
- 角色档案；
- 用户档案；
- 世界书；
- 结构化、实时、日记和向量记忆；
- 时间、天气、提醒、收藏；
- 聊天历史和本轮输入；
- CoT、输出协议；
- Tools、请求参数和Provider包装。

主私聊在真实 request body 完成后调用：

```javascript
OVOContextSourceRegistry.buildShadowManifest(...)
```

Manifest 被保存到：

- `window.__ovoLastContextManifest`；
- `sessionStorage.ovo_last_context_manifest`；
- 当前操作的模型请求记录 `contextManifest`。

### 当前限制
V5.4.0 仍由旧聊天逻辑构造最终 Prompt。注册表负责影子登记和对账，不是唯一编译器。因此 `coverage.unregisteredSystemChars` 可能大于0，这是本阶段需要识别的迁移差额，而不是伪装成“已经全部注册”。V5.4.1 才会用统一 ContextCompiler 接管主聊天。

## 五、悬浮球边界
删除悬浮球中的：

- 能力覆盖页面及入口；
- 本次聊天记忆 Payload 核验折叠项；
- 操作报告复制、下载；
- 操作历史报告导出；
- Proment入口。

保留：

- 当前操作状态和阶段；
- 取消操作；
- 模型列表、刷新和切换；
- Git上传、恢复和设置；
- 开发日志筛选、复制和清空；
- 操作历史及子操作；
- 模型请求详情；
- Prompt来源摘要和来源跳转；
- 数据变化；
- 错误详情。

Proment仍作为独立设置页面存在，不再属于悬浮球。

## 六、下一阶段
V5.4.1 将完成主聊天统一编译：

1. 所有来源通过 Registry 收集；
2. 统一去重、优先级、预算和裁剪；
3. Proment开关真实控制最终请求；
4. 最终来源、Tools和参数逐项对账；
5. `chat_ai.js` 不再直接理解世界书和记忆内部匹配规则。
