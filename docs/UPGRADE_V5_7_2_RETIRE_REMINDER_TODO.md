# QWQ V5.7.2：删除独立提醒/待办，统一使用角色记忆表

## 最终行为

独立的“提醒事项/待办”功能已整体删除。程序不再提供提醒 App、提醒日历、新建提醒弹窗、到期轮询、通知、聊天指令或角色提醒设置。

待办统一记录在每个角色自己的结构化记忆中：

```text
角色记忆
└─ 待办与近期事项（原 v5_recent_events）
```

表 ID 继续保持 `v5_recent_events`，因此原来已经存在于记忆表中的记录不需要迁移，也不会因为改名而丢失。

## 已删除内容

- 首页/聊天扩展面板中的“提醒”入口；
- `reminder-screen` 日历页面和新建/编辑弹窗；
- `js/modules/reminder.js`；
- `css/modules/reminder.css`；
- 角色设置“允许角色管理提醒事项”；
- 聊天设置“聊天内显示提醒事项消息”；
- `[创建提醒：时间|内容]`；
- `[创建待办：时间|内容]`；
- `[完成待办：关键词]`；
- 每 30 秒检查到期事项的计时器；
- 到期系统通知与自动插入聊天消息；
- 模型请求中的提醒/待办提示词及 Token 分类；
- Context Manifest 中的 `reminder.active` 来源；
- Proment 对提醒页面的跳转。

## 记忆表调整

原“近期事项”表改名为“待办与近期事项”，继续使用相同 ID 和 Rows 数据结构。

事项状态保留：

- 待办；
- 已发生；
- 已完结。

用户或角色明确提出需要执行、等待或跟进的事项时，动态记忆可写入这张表；同一事项出现进展时更新原记录。

### 待办不会因 15 天期限自动失效

表中的普通近期事项仍使用 15 天引用期限，但“事项状态 = 待办”的记录会一直保留在可用记忆中，直到状态被改为“已发生”或“已完结”。这样删除独立待办功能后，长期未完成的事项不会被当作普通短期事件过期。

## 旧提醒数据处理

用户确认旧提醒数据无需转换，因此本版首次加载角色数据时直接删除以下旧字段，并立即写回 IndexedDB：

```text
reminders
charReminderEnabled
showReminderMsg
```

不会把旧提醒自动转换成记忆表记录，也不会保留隐藏的提醒调度数据。

旧聊天历史中已经存在的提醒系统消息不会继续触发功能；它们仅作为普通历史文本保留。程序不会再生成新的提醒消息。

## 未受影响

- 收藏记忆和标签召回；
- 收藏方字段；
- 悬浮球只读请求观察；
- 其他结构化记忆表；
- 世界书、日记、小剧场、搜索等功能；
- 现有 `v5_recent_events` 记忆记录；
- `STORE_VERSION=3`，不会重建角色记忆仓库。
