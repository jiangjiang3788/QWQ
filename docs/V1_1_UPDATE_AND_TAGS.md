# V3 第一版修订 1.1：更新提示、表格布局与分类标签说明

## 1. 每轮更新提示

每次私聊AI回复处理完毕后，都会出现一次记忆结果提示：

- 有写入：`本轮记忆已更新：当前状态（更新2）；近期事件（新增1）`
- 没有写入指令：`本轮记忆：没有需要更新的内容`
- 写入不符合表规则：`本轮记忆：没有写入（2项不符合规则）`
- `<memory_ops>` JSON损坏：`本轮记忆：更新指令解析失败`

提示只说明本轮记忆处理结果，不占用聊天状态栏。可以在“记忆设置”中关闭。

## 2. KV与Rows

### KV

- 一张表只保留一条正式记录。
- 页面采用纵向两列：左边字段名，右边字段值。
- 适合当前状态、基础资料、偏好等“一项一值”的内容。
- 编辑弹窗同样采用左字段、右值布局。

### Rows

- 一张表可保存多条记录。
- 页面采用横向表格。
- 单元格文字超过80字时显示省略号；悬停保留完整内容。
- 进入编辑弹窗后始终显示完整文字。

### 事件ID

- 系统已有真正的 `record.id`，不需要再把事件ID显示为业务字段。
- 名为“事件ID / 事件编号 / Event ID”的动态字段会默认隐藏。
- 隐藏只影响显示、编辑和AI字段提示，不会主动删除旧值。
- 表设置中的每个字段也可以手动勾选“隐藏”。

## 3. USER状态栏

聊天顶部的细状态栏只用于显示USER当前状态，不再显示“几张短期表、几张中期表”等系统运行信息。

设置方法：

1. 打开一张短期KV表的“表设置”。
2. 勾选“用这张表显示USER当前状态”。
3. 保存。

系统只允许一张表作为状态栏来源。状态栏显示该表中非空字段的“字段：值”，最多显示8项；长值仅在状态栏中缩短，表格和编辑器中的原文不受影响。

## 4. 分类和标签到底做什么

### 分类

分类是记录的一个主要主题，一条记录只有一个分类，例如：

- 身体状态
- 当前任务
- 人际关系
- 软件项目
- 日常经历

它相当于一个“大抽屉”。

### 标签

标签是更具体的关键词，一条记录可以有多个，例如：

- 睡眠不足
- 记忆系统
- 紧急
- 周末
- 始终注入

它相当于贴在记录上的多个“小贴纸”。

## 5. 分类标签参与的三处判断

### A. 短期自动写入目标表

每张短期表可以设置：

- 允许分类
- 允许标签

AI生成一条记忆操作时，代码会检查：

- 分类命中允许分类；或者
- 至少一个标签命中允许标签。

满足任意一个即可写入。两项都为空表示这张表不限制分类标签。

这一步决定“记忆写到哪张表”。它是代码校验，不只是提示AI。

### B. 中期积累来源

中期表从指定短期表读取新增正式记录，再按以下条件过滤：

- 分类过滤
- 包含标签
- 排除标签

通过后才参与中期总结。它决定“哪些短期记录可以被积累”。

### C. 聊天上下文引用

发送下一轮聊天前，系统读取最近12条聊天文字并匹配正式记录：

1. 表必须开启“允许进入上下文”。
2. 记录不能带全局“禁止注入”标签。
3. 必须通过该表的限定分类、必须含标签和排除标签。
4. 记录分类或记录标签需要实际出现在最近聊天文字中；带全局“始终注入”标签的记录除外。
5. 按分数排序后取全局最大记录数。

当前评分：

- 始终注入：+1000
- 分类出现在近期聊天：+40
- 每个命中的标签：+20
- 记录7天内更新：+5

注意：当前引用匹配是“文字包含匹配”，不是额外调用AI做语义分类。因此“睡眠”能匹配“昨晚睡眠不好”，但“休息质量差”不一定匹配标签“睡眠不足”。需要语义匹配时，后续可增加同义词配置，而不是恢复向量数据库。

## 6. 配置建议

- 分类使用稳定、较宽的主题，不要写成长句。
- 标签使用聊天中可能自然出现的短词。
- USER状态表建议：短期 + KV + 随聊天写入 + 作为状态栏来源。
- 中期表建议设置明确来源表和包含标签，避免把无关短期记录混合总结。
- 长期表仍只允许手动修改。
