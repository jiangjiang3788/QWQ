# QWQ V5.8.3：角色收藏恢复为私人情感动作

## 为什么 V5.8.2 的方向不对

V5.8.2 用“重要信息标准、每轮最多一条、低信息量拒绝、寄语理由校验”控制收藏。这样会让模型把收藏理解为每轮都要做一次的信息分类和数据库写入，而不是角色在关系中自然产生的动作。

收藏的正确含义是：角色看到某句用户原话后，出于自己的情绪、关系和当时语境，产生“我想把这句话留下来”的冲动。它不要求这句话包含长期事实，也不要求内容长或信息密度高。

## 新语义

- 收藏不是记忆整理、信息提取、重要性评分或每轮后台任务。
- 一句“嗯”、一次“晚安”、玩笑、情话或普通回答，都可能因为当时语境对角色有意义。
- 不设置每轮数量配额，也不要求角色每轮检查是否收藏。
- 一次真实情境中自然想收藏多条时，可以分别收藏。
- 收藏和结构化记忆不是二选一：同一条消息可作为事实进入记忆，也可因为原话本身被收藏。

## 实现调整

1. 提示词改为“角色的私人收藏能力”，不再列长期价值、信息量等数据标准。
2. 当前请求中所有真实用户消息都可成为收藏对象，不局限于本轮尚未回复的消息。
3. 消息定位 ID 收进 `<message_meta id="...">`，不再在正文前显示 `[id:...]`。
4. 角色实际决定收藏时使用 `[FAVORITE:消息ID:可选的私人寄语]`；寄语允许为空。
5. 模型不再生成标签、标题和正文。程序从原消息读取正文，并在写入后自动生成标签。
6. 解析器不限制每轮数量；同一回复中自然产生多个收藏动作时可逐条执行。
7. 程序只校验消息归属、消息是否存在和同一具体消息是否已被该角色收藏。
8. 不再拒绝短句、表情式回应、空寄语或相似正文。相同文字在不同时间出现可以分别收藏。

## 保留不变

- 用户手动收藏不受影响。
- 收藏仍写入当前角色的“收藏记忆”表。
- 后台主动回复、总结、独白和线下节点仍不触发角色自主收藏。
- 旧 `<favorite_ops>` 输出仍可解析，便于兼容缓存中的旧提示词或模型习惯。
