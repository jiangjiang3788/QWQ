QWQ V5.8.1 测试报告
====================

一、测试范围

1. 全部 JavaScript 文件执行 node --check 语法检查。
2. 执行 tests 目录全部 22 个测试文件。
3. 使用用户提供的实际精简备份进行只读 Prompt 生成验证。
4. 专项检查默认私聊、自定义 Prompt、剧情节点、通话、日记、小剧场和来源清单。

二、结果

- JavaScript 语法检查：通过。
- 测试文件：22 个成功结束，失败 0。
- 其中 1 个旧迁移测试因专用私人 fixture 不存在，按原设计明确跳过；不是失败。
- 实际备份只读验证：通过。

三、V5.8.1 专项覆盖

1. 自定义 Prompt 使用与默认私聊相同的项目顺序。
2. 旧完整自定义模板中的世界书、人设、记忆、环境和输出结构占位会自动去重。
3. 自定义额外规则保留在“08 自定义规则”，并正确替换 {{user}} / {{char}}。
4. 剧情节点使用统一项目骨架。
5. 节点指令和扩展规则进入“07 当前环境”。
6. 线下节点文风世界书进入“05 世界书·场景后置”。
7. 节点关闭读取记忆时保留核心档案，只移除动态长期/当前记忆。
8. 线下节点不发送角色自主收藏写入协议。
9. 通话请求复用核心档案、三段世界书和分层记忆。
10. 通话前文字历史遵守 Proment 历史策略。
11. 私聊日记复用核心档案，并独立登记实际聊天来源、世界书和日记参考。
12. 手动与角色主动小剧场复用核心档案。
13. 非聊天任务的“任务指令”只保留未被其他来源覆盖的剩余文本，不再重复整份 Prompt。
14. 悬浮球来源顺序与最终项目顺序一致。
15. 核心档案仍为唯一身份来源；旧 persona/myPersona 只在核心档案为空时回退。

四、回归覆盖

- 记忆动态字段和 KV 单例迁移；
- 结构化记忆编译与写入；
- 上下文编译器和统一 AI 网关；
- 来源治理与请求审计；
- 悬浮球折叠、分组、滚动与请求只读；
- 历史无上限设置；
- 收藏转入角色记忆和标签召回；
- 收藏发送上限设置；
- 独立提醒/待办移除；
- 世界书统一预算、完整条目选择及三个真实插入位置；
- 核心档案字段分组与别名替换。

五、数据安全

实际备份仅用于本地只读验证。代码包和测试报告不包含备份中的聊天正文、记忆正文、API 密钥或其他私人数据。
